## 2025-03-05 - Fix Error Information Leakage
**Vulnerability:** Found 7 instances in `server.ts` where internal application errors and stack trace details (`error.message`) were passed directly back to clients in `500 Internal Server Error` responses. In addition, the Express `x-powered-by` header was enabled, disclosing the server technology stack.
**Learning:** This is a systemic issue across all API endpoints indicating a missing centralized error handling pattern. Returning raw errors to clients breaks the principle of "fail securely" and could expose sensitive data like internal paths, query syntax, missing environment variables (e.g. GEMINI_API_KEY), or downstream service failures.
**Prevention:** Always log the original error internally (e.g., `console.error`) and return a generic, safe error message to the client. Consider implementing a global error handling middleware in Express to catch all exceptions and format them consistently, rather than handling it individually in every route block. Additionally, always disable the `x-powered-by` header using `app.disable("x-powered-by");`.
